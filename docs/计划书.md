# 台风实况信息展示网站 · 项目计划书

> 版本：v1.0 ｜ 编制日期：2026-11-10 ｜ 状态：草案

---

## 一、项目背景与目标

我国是世界上受台风影响最严重的国家之一，沿海及近海居民每年台风季都面临生命财产损失风险。当前问题：

- 气象信息分散在多个官方平台，专业术语多、普通居民难快速理解；
- 移动端在恶劣天气下的体验差，关键信息不突出；
- 预警发布后，居民往往不清楚"我该做什么"。

**项目目标**：打造一个面向沿海居民、实时、易读、带分级预警的台风信息网站，让普通人一眼看懂——

> **台风叫什么 · 现在在哪 · 往哪走 · 风多大 · 要不要防**

**设计原则**：移动端优先、信息降噪、权威为准、零门槛阅读。

---

## 二、目标用户

| 用户群体 | 特征 | 核心诉求 |
|---|---|---|
| 沿海社区居民 | 非专业、手机为主 | 快速知道要不要撤离/防范 |
| 渔民 / 养殖户 | 海上/近海作业 | 路径与风力直接关系生计安全 |
| 沿海游客 | 临时逗留 | 即时风险提醒与避险指引 |
| 基层防灾人员 | 辅助参考 | 多台风并存的态势总览 |

**使用场景**：台风季随时查看；预警升级时秒级获取防御行动建议。

---

## 三、核心功能需求

必须包含的五大实况信息字段（用户明确指定）：

1. **台风名称 / 编号**
   - 国际编号（如 2026 年第 X 号台风）、中文名与英文名
   - 当前强度等级（热带风暴 / 强热带风暴 / 台风 / 强台风 / 超强台风）

2. **当前位置**
   - 实时经纬度
   - 距最近陆地 / 重点城市的距离与方位（如"距 XX 市东南约 320 公里"）
   - 在海图 / 地图上的精确定位点

3. **移动路径与方向**
   - 过去已发生轨迹（实线）
   - 未来预报路径（虚线）+ 各时间点位置
   - 移动方向（西北 / 东北 / 西行等）、移动速度（km/h）

4. **风力强度**
   - 中心附近最大风力（级）、最大风速（m/s）
   - 中心最低气压（hPa）
   - 七级 / 十级风圈半径

5. **分级预警**
   - 国家四级预警体系（蓝 / 黄 / 橙 / 红）
   - 每种级别的含义、发布标准、给居民的具体防御指南

---

## 四、分级预警机制（中国气象预警体系）

采用国家统一的台风预警信号四级制，颜色由低到高：

| 级别 | 颜色 | 含义 | 发布标准（示例） | 居民防御要点 |
|---|---|---|---|---|
| IV 级 | 🔵 蓝色 | 一般 | 24h 内可能/已受影响，平均风力达 6 级以上 | 关注动态，固定门窗、收好阳台物品 |
| III 级 | 🟡 黄色 | 较重 | 24h 内风力达 8 级以上 | 停止露天活动，渔船回港，加固设施 |
| II 级 | 🟠 橙色 | 严重 | 12h 内风力达 10 级以上 | 停课停工，危险区域人员转移准备 |
| I 级 | 🔴 红色 | 特别严重 | 6h 内风力达 12 级以上 | 紧急撤离，全员避险，听从指挥 |

> 注意：具体标准以中央气象台最新发布口径为准，本表为通用参考。
> 网站顶部以"最高预警横幅"形式高亮当前生效的最高级别预警。

---

## 五、信息展示与页面设计

**整体风格**：大字号、高对比、关键信息首屏直达；移动端优先、响应式适配。

- **首页看板**：当前活跃台风卡片（名称、强度、位置、风力大数字突出）+ 顶部最高预警横幅
- **路径地图**：台风位置 + 历史/预报路径叠加在地图上（支持缩放、定位到用户城市）
- **预警详情页**：分级色彩背景 + 防御措施清单（可勾选"我已做到"）
- **防御指南 / 科普**：台风常识、避险手册、应急联系人

**无障碍与极端环境**：高对比配色、大触控目标、弱网下核心信息仍可加载。

## 六、数据源方案

| 来源 | 说明 | 用途 |
|---|---|---|
| 中央气象台台风网（nmc.cn） | 国内权威、实时台风公报 | 主数据源 |
| 中国气象局 / 地方气象台 | 预警信号发布 | 分级预警 |
| 日本气象厅（JMA）/ JTWC | 国际路径参考 | 交叉校验（可选） |

**数据策略**：
- 后端定时抓取（建议 5–15 分钟一次）→ 缓存为 JSON
- 前端轮询或 WebSocket 推送更新
- **必须标注数据来源与发布时间，并声明"以官方发布为准"**

## 七、技术架构（建议）

```
[气象数据源] → [后端抓取/缓存服务] → [API] → [前端展示]
                                          ↑
                                    [预警分级引擎]
```

- **前端**：轻量框架（React / Vue）或纯 HTML+JS；地图用 Leaflet / 高德 / 天地图
- **后端**：Node.js 或 Python 定时任务，负责抓取、清洗、缓存、预警判定
- **数据**：JSON 缓存 + 定时刷新；关键字段结构化存储
- **部署**：静态前端托管 + 轻量后端服务；考虑 CDN 加速与多节点容灾

> 技术栈为建议方案，可在实施第一阶段根据团队情况最终确定。

## 十、风险与注意事项

1. **数据权威性**：以官方为准，不做预测性误导；显著标注来源与时间。
2. **实时性**：台风变化快，需高频更新与失效兜底（旧数据标注"已过期"）。
3. **可用性**：恶劣天气下网络/服务器可靠性，需容灾与降级方案。
4. **合规**：气象数据使用授权、版权与署名；不采集用户隐私。
5. **安全**：防刷、防注入；预警信息不可被篡改。
